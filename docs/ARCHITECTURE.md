# 架构与实现边界

## 运行路径

中文面板 → 本机 HTTP 服务 → 校验过的工具箱操作 → VectorCraft 官方 JSON 控制协议 → 桌面画稿。

- `app.py`：本机服务、启动专用窗口、设置与预设、来源/令牌校验。
- `protocol.py`：有超时与大小上限的逐行 JSON 客户端。每次使用新连接；编辑请求永不自动重放。
- `layout.py`：纯坐标算法。以 pt 为单位，y 轴朝下。
- `engine.py`：读取选择、验证边界/修订/文档、组合引擎命令、撤销分组和标签元数据。
- `web/`：无外部 CDN 或运行依赖的中文页面。通过按钮显式刷新选择，避免隐藏的自动编辑。

## 与 SCI Toolbox 的区别

SCI Toolbox 面板调用 Adobe CEP 的 `CSInterface/evalScript`，后端依赖 Illustrator DOM。本项目没有提供 CEP 模拟器，也没有将其脚本直接注入 VectorCraft；全部布局、标签和连接程序独立实现。

VectorCraft 的 WebAssembly 扩展接口主要接收路径对象，不适合完整的图片与可编辑文字组图面板。因此首版使用官方桌面控制协议，不改 VectorCraft 二进制，也不重编其界面。

## 撤销与失败处理

1. 提交前验证参数、文档修订、活动文档和当前选择。
2. 打开 `edit.undoGroup.begin`，执行经过验证的命令。
3. 正常结束时恢复原始选择并关闭撤销分组。
4. 引擎明确拒绝时，以 `cancel: true` 取消分组并回滚已执行步骤。
5. 网络中断等结果不确定时，不发送重复编辑或自动猜测回滚。暂停新操作，要求用户检查画稿后恢复。

这不是跨进程事务：VectorCraft 的键盘、鼠标编辑可能和控制调用交错。操作期间应暂停手动编辑。应用崩溃或退出时，由 VectorCraft 的正常恢复机制负责，工具箱不声称能恢复所有情况。

## 标签和边框

以独立文字/矩形对象创建。使用对象 `attrs.data` 中的 `sci-role`、`sci-target` 保存关联，名称分别以 `[SCI label]`、`[SCI border]` 开头。更新时只匹配本工具箱创建且仍可编辑的对象。

关联 ID 在原生画稿保存与重开中已验证。向另一文档复制对象后 ID 可能改变，首版不承诺跨文档自动修复关联。原图删除后残留标签或边框由用户手动删除。移动或缩放原图后需再次运行更新。

## 本机隔离

网页服务只监听 `127.0.0.1`，检查 Host、Origin 和每次启动随机产生的会话令牌；没有通用任意命令、任意文件下载或上传路由。设置文件只保存界面参数及路径。

VectorCraft 控制端口由上游提供，本身没有鉴权。专用窗口限定自动化读写根目录、采用独立配置目录。上述设置不抵御同一用户权限下的其他恶意本机程序，不应把端口转发到网络。

## 后续方向

在验证首版后再评估局部放大、真实标定比例尺、图像通道处理和软件内部面板，不将这些功能列为已支持。
